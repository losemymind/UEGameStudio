# GDD 模板 — 单系统游戏设计文档

> 由 `design-system` 技能强制使用。系统 GDD 必须包含以下 **8 个必节**；缺失必节 = 未完成（设计评审门 ADVISORY 但不可进入开发，除非显式豁免）。

## 系统名称：[系统名]

**优先级**：[高/中/低]
**层级**：[核心支柱 / 子系统 / 旁支]
**状态**：Draft | In Review | Approved | Under Revision

---

## 1. Overview（概述）

- 该系统解决什么核心问题/玩家痛点
- 一句话玩家价值主张
- 与游戏支柱（pillar）的关联（服务哪条支柱，不违反哪条）

## 2. Player Fantasy（玩家幻想）

- 这个机制让玩家"成为/做到"什么
- 传递什么力量感/情感
- 目标 MDA 美学（按优先级排列）

## 3. Detailed Design（详细设计）

### 机制：[子机制名]
- **目的**：为什么存在
- **输入**：[按钮 / 触发器 / 计时器 / 事件]
- **输出**：[状态变化 / 资源变化 / 世界变化]
- **成功判定**："正常运作"的表现
- **失败状态**：出错时会发生什么
- **边界情况**：
  - 如果 [X] 同时发生怎么办？
  - 如果玩家拥有 [最大/最小] 资源怎么办？
- **调节杠杆**：[控制手感/平衡的变量列表]
- **依赖**：[涉及的其他系统]

（每个子机制重复此结构）

## 4. Formulas（公式）

> 每个公式必须含：命名表达式 + 变量表 + 输出范围 + 工作示例（systems-designer 强制标准）

```yaml
formula:
  name: 公式名称
  expression: 数学表达式
  variables:
    - symbol: 变量符号
      type: float/int/curve
      range: [min, max]
      description: 变量含义
      ue5_source: DataTable列 / CurveTable键 / GameplayTag
  output_range: [min, max]  # 说明为何钳制/不钳制
  example: 具体数值代入示例
```

## 5. Edge Cases（边界情况）

- [ ] 空状态（无资源/无目标/无输入）
- [ ] 满状态 / 溢出
- [ ] 同时触发
- [ ] 数值边界（最小/最大/负值）
- [ ] 玩家中途退出/断线
- [ ] 与已有系统交互的冲突场景

## 6. Dependencies（依赖）

- **上游依赖**：本系统读取哪些系统的数据/接口
- **下游依赖**：哪些系统读取本系统的数据
- 每个依赖标注：接口签名 / 数据格式 / 版本契约
- 未设计完成的依赖：定义临时契约并显式标记

## 7. Tuning Knobs（调节杠杆）

| 参数 | 默认值 | 范围 | 调节影响 | UE5 配置位置 |
|---|---|---|---|---|
| 参数名 | 默认 | [min,max] | 调节后玩家体验如何变化 | DataTable/DataAsset/GE |

> 所有未定值标 `[PLACEHOLDER]`；每个参数必须说明"调大/调小分别导致什么"。

## 8. Acceptance Criteria（验收标准）

- [ ] 验收标准 1（可测试、可度量、二值判定）
- [ ] 验收标准 2
- [ ] 每个标准必须满足："测试者能明确判断通过/失败"
