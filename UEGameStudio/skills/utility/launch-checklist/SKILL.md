# 最终上线门

跨所有部门验证发布就绪度：代码、内容、QA、商店与分发、基础设施、社区与营销、运营，最终给出 Go / No-Go 决定与各部门签字。仅在用户显式以 `/launch-checklist` 调用时运行，不自动触发。

> **分工**：本技能是**最终公开发布门**（一次真正的上线，覆盖营销/社区/法律/运营）。**单个版本**的发布前校验（构建/认证/商店/质量，每个版本可跑）是 `release-checklist` 的职责。顺序：`/release-checklist`（版本级，可多次）→ `/launch-checklist`（最终上线，通常一次）。本技能可引用 `release-checklist` 的构建/认证结论作为输入，不重复校验。

## 何时使用
- 临近正式上线日期，需要一次性覆盖所有部门的上线就绪校验
- 需要正式 Go/No-Go 决定与跨部门签字
- 需要做 dry-run（只生成清单、不写文件、不产生签字条目）

## 流程
### 解析参数
1. 读取上线日期参数或 `dry-run` 模式（dry-run 只生成清单，不写文件）。

### 收集项目上下文
1. 读取 `AGENTS.md`（技术栈、目标平台、团队结构）、最新里程碑、既有发布清单、内容日历。

### 扫描代码库健康
1. 统计 `TODO`/`FIXME`/`HACK` 注释及位置。
2. 检查遗留的调试输出（`console.log`/`print()`）、占位资产（`placeholder`/`temp_`/`WIP_`）、硬编码测试/开发值（localhost、测试凭据、调试开关）。

### 生成上线清单
1. 按 7 大块生成可勾选清单：
   - 代码就绪（构建健康、代码质量、安全）
   - 内容就绪（资产、文本与本地化、游戏内容）
   - 质量保证（测试、平台认证、性能）
   - 商店与分发（商店页、法律）
   - 基础设施（服务器、分析与监控）
   - 社区与营销（社区就绪、营销）
   - 运营（团队就绪、Day-One 计划）
2. 产出 Go/No-Go 决定：READY / NOT READY / CONDITIONAL，列出阻塞项、条件项与所需签字人（创意总监、技术总监、QA 负责人、制作人、发布经理）。

### 保存清单
1. 展示清单与摘要（总项数、阻塞项、条件项、未完成部门）；非 dry-run 时经确认写入 `production/releases/launch-checklist-[date].md`。

### 后续步骤
1. 运行 `/gate-check` 获取正式 PASS/CONCERNS/FAIL 结论；通过 `/team-release` 协调签字。

## 输入/输出
- 输入：项目技术栈/平台/团队、里程碑、既有发布清单、代码库状态
- 输出：跨部门上线清单 + Go/No-Go 决定 + 签字项（可写为 `launch-checklist-[date].md`）

## 约束
- 仅显式调用，不基于上下文自动触发。
- 阻塞项必须在上线前解决；TODO/FIXME 上线前应为零（HACK 需有书面理由）。
- 安全检查覆盖：不暴露密钥、存档加密、网络加密（TLS/DTLS）、反作弊、服务端输入校验、隐私合规（GDPR/CCPA）。

## 反例（不要这样）
- 只检查代码、忽略商店页/营销/社区/法律——上线当天才发现商店素材或 EULA 没准备好。
- 自动触发而不是等待显式调用——在非上线节点反复跑全量清单制造噪音。
- 忽略调试输出与硬编码测试值——把测试凭据或 localhost 地址带进生产构建。
- 没有 Go/No-Go 与签字人就宣布"就绪"——上线决定缺少明确责任归属。

## 反合理化表（借口 → 反驳）
| 借口（会怎么说） | 反驳（为什么不对） |
|---|---|
| 「代码就绪就行，商店页/营销/法律等上线前一天再说」 | 上线门覆盖 7 大部门，忽略商店页/EULA/营销会在上线当天才发现素材缺失。 |
| 「有几个调试输出和 localhost 没清理，不影响」 | 调试输出与硬编码测试值会把测试凭据/localhost 带进生产构建，是安全隐患。 |
| 「检查完给个『就绪』结论就完了，不需要签字人」 | 无 Go/No-Go 与签字人，上线决定缺少明确责任归属。 |

## Red Flags（违规信号）
- 清单只有代码/内容，缺少商店与分发、社区与营销、运营、基础设施部门。
- 未扫描调试输出（console.log/print()）、占位资产（placeholder/temp_/WIP_）、硬编码测试值。
- 结论只有「就绪/未就绪」两态，缺少 CONDITIONAL 与签字人列表。

## Verification（证据化验证门）
- [ ] 7 大块全部覆盖，且每块含可勾选条目。
- [ ] 扫描项含调试输出、占位资产、硬编码测试/开发值的位置。
- [ ] 结论为 READY/NOT READY/CONDITIONAL 之一，并列出阻塞项、条件项与签字人。
- [ ] 非 dry-run 时才写 launch-checklist-[date].md，dry-run 只展示不写文件。
