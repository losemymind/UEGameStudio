# 接下来做什么

## 何时使用
- 用户问"接下来该做什么 / 现在该做什么"
- 用户表示卡住、迷茫、不知道该做什么
- 需要快速定位在流水线中的位置与下一必做步骤

## 流程
### 读取目录与未收录技能
1. 读取工作流 catalog（各阶段、步骤顺序、必做/可选、完成工件）。
2. Glob 已安装技能，找出未出现在 catalog 中的"未收录技能"，作为脚注展示。

### 确定当前阶段
1. 优先读 `production/stage.txt`；缺失则按工件从最先进往回推断（源码文件数、story、ADR、systems-index、game-concept）。

### 读取会话上下文
1. 读 `session-state/active.md`，提取最近在做的事、进行中的任务与开放问题。

### 检查步骤完成度
1. 对当前阶段每个步骤做工件检测：有 glob 用 Glob 核对，有 pattern 用 Grep，仅 note 标 MANUAL，无工件标 UNKNOWN。
2. 生产阶段特例：直接读 `sprint-status.yaml`（in-progress/ready-for-dev/done/blocked），替代逐条工件扫描。

### 定位下一步
1. 确定最后完成的必做步骤、当前阻塞的必做步骤（唯一主推荐）、可选机会、以及后续即将到来的步骤。

### 输出结果
1. 简短直接输出：✓ 已完成 / → 当前必做（仅一条）/ ~ 可选 / 后续；接近阶段门时提示 gate-check。

## 输入/输出
- 输入：catalog、阶段文件、会话状态、工件目录。
- 输出：短小精悍的定位报告（你在哪、下一步做哪一件事）。

## 约束
- 只读，不写任何文件。
- 绝不自动运行下一个技能，只推荐。
- 主推荐只给一件"必做"事，可选与"即将到来"是次要上下文。
- 对 MANUAL 步骤要询问而非臆断完成。

## 反例（不要这样）
- 输出六条并列建议让用户更迷茫，而非一条主推荐。
- 把可选步骤当成必做步骤推到主推荐位。
- 自动替用户执行推荐的技能。
- 把它写成完整审计报告（那是 project-stage-detect 的职责）。
