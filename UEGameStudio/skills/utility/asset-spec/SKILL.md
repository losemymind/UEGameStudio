# 逐资产视觉规格 + AI 生成提示

从 GDD、关卡文档或角色档案生成逐资产视觉规格与 AI 生成提示。产出结构化规格文件并更新主资产清单。规格始终锚定美术圣经（art-bible）的视觉规则与资产标准——与美术圣经矛盾的规格就是错的。

## 何时使用
- 美术圣经与 GDD/关卡设计已批准、生产开始前
- 需要为每个视觉实体/UI 屏幕/HUD 元素产出规格与 AI 生成提示
- 需要建立或更新实体清单与资产清单

## 流程
### 解析参数 / 实体清单
1. 无参数时：若有 `entity-inventory.md` 或 `asset-manifest.md`，找下一个状态为 Needed 的条目并询问；若都没有，先走实体与屏幕清单流程（`entity-inventory.md`）。
2. 有参数：提取目标类型（system/level/character）、目标名（kebab-case）、评审模式（full/lean/solo）。

### 收集上下文
1. 必读：`design/art/art-bible.md`（缺失则停止并提示 `/art-bible`，提取视觉身份、色彩系统、形状语言、资产标准）、技术偏好（性能预算、命名规范）。
2. 按目标类型读源文档：system 读 GDD 的 Visual/Audio Requirements；level 读关卡文档；character/entity 读角色档案或实体清单（无档案则询问用户简述）。
3. 可选：既有资产清单与相关规格（避免重复，识别可复用资产）。

### 资产识别
1. 从源文档提取所有显式与隐含资产，按 Sprite/2D、VFX/粒子、Environment、UI、Audio、3D 分类。
2. 展示分组清单，经 `AskUserQuestion` 确认后才进入规格生成。

### 规格生成
1. 按评审模式派发（Task 同时并发）：
   - full：art-director（视觉描述 + AI 生成提示 + 引用的美术圣经条款）+ technical-artist（尺寸/面数、格式、命名、引擎约束、LOD），并行。
   - lean：仅 art-director；solo：主会话按美术圣经规则直接写，注明技术约束未验证。
2. 收集两者输出，冲突（如 4K 纹理 vs 引擎 512px 预算）显式暴露，不静默取舍。

### 编译与评审
1. 按 `ASSET-NNN` 格式生成每资产规格（分类/尺寸/格式/命名/面数/纹理分辨率/视觉描述/美术圣经锚点/生成提示/状态）。
2. 经 `AskUserQuestion` 批准或修订。

### 写规格文件与更新清单
1. 经确认写 `design/assets/specs/[target-name]-assets.md`，并更新/创建 `design/assets/asset-manifest.md`。

### 收尾
1. 用 `AskUserQuestion` 提供下一个动作（继续规格化/审计/停止）。

## 输入/输出
- 输入：美术圣经、GDD/关卡/角色文档、技术偏好、既有清单/规格
- 输出：逐资产规格文件（`design/assets/specs/*.md`）+ 更新后的资产清单

## 约束
- 每个阶段遵循 识别→确认→生成→评审→批准→写入；未经确认不规格化资产。
- 规格必须锚定美术圣经；表面所有 agent 分歧，不静默选边。
- 资产 ID 全项目顺序分配（从清单最高号 +1），跨上下文唯一稳定。
- 写入规格文件与更新清单均需批准；audio 只写描述、不给生成提示。

## 反例（不要这样）
- 未确认资产清单就开写规格——跳过"识别→确认"协议。
- 生成与美术圣经矛盾的规格——规格脱离视觉规则与资产标准。
- 静默忽略 art-director 与 technical-artist 的冲突——应显式暴露供决策。
- 重复创建已存在的通用资产规格而不复用 ASSET-ID。

## 反合理化表（借口 → 反驳）
| 借口（会怎么说） | 反驳（为什么不对） |
|---|---|
| 「资产清单先别确认了，直接写规格省时间」 | 跳过识别→确认协议会生成范围错误或重复的规格。 |
| 「美术圣经和 TA 建议冲突，我选一个更合理的」 | 分歧必须显式暴露供决策，静默选边会埋下美术方向与技术预算的错配。 |
| 「这个资产之前有过，我重新写一份也行」 | 应复用既有 ASSET-ID，重复创建破坏跨上下文唯一的资产清单。 |

## Red Flags（违规信号）
- 规格中缺少美术圣经锚点字段，或规格内容与美术圣经规则矛盾。
- 未展示资产清单确认就进入规格生成。
- art-director 与 technical-artist 输出冲突被静默合并。

## Verification（证据化验证门）
- [ ] 每份规格含分类/尺寸/格式/命名/美术圣经锚点/生成提示/状态，ID 为全项目顺序分配。
- [ ] 识别→确认→生成→评审→批准→写入各阶段均有确认痕迹。
- [ ] 冲突被显式列出并交付决策；写规格文件与更新清单前均已批准。
