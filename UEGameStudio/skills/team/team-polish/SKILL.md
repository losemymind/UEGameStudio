# 打磨团队编排

## 何时使用
- 功能/区域已实现但需优化、打磨、加固到发布质量
- 需要性能分析、引擎层优化、视觉/音频打磨、QA 加固

## 流程
### 阶段 0：解析评审模式
- `--review` > `production/review-mode.txt` > `lean`（含总监门跳过规则）

### 团队组成（哪些 agent 参与）
- **performance-analyst** — 剖析、优化、内存分析、帧预算
- **unreal-engine-programmer** — 引擎层瓶颈（渲染/内存/资源加载，按需调用）
- **technical-artist** — VFX 打磨、着色器优化、视觉质量
- **sound-designer** — 音频打磨、混音、环境层、反馈音
- **unreal-tools-programmer** — 内容管线/编辑器工具验证（按需调用）
- **qa-tester** — 边界、回归、浸泡测试

### 阶段 1：评估（performance-analyst）
- 用 perf-profile 剖析、定位瓶颈与帧预算违规、测内存与泄漏、对标目标硬件，输出优先优化清单

### 阶段 2：优化（performance-analyst + 按需 unreal-engine-programmer）
- 修热点、减少 draw call/过度绘制、修泄漏、验证不改变玩法；引擎层根因交 unreal-engine-programmer 并行修

### 阶段 3：视觉打磨（与阶段 2 并行）
- technical-artist 审 VFX 一致性、优化粒子/着色器、加屏幕震动/镜头效果、低画质优雅降级

### 阶段 4：音频打磨（与阶段 2 并行）
- sound-designer 查音频事件完整性、混音电平、加环境层、验空间定位

### 阶段 5：加固（qa-tester）
- 边界条件、快速输入、浸泡测试、压力测试（最大实体/最坏情形）、回归测试、最低配置测试

### 阶段 6：签署
- 对比性能指标与预算，报 READY FOR RELEASE / NEEDS MORE WORK，列出遗留问题及严重度

## 输入/输出
- 输入：目标功能/区域、性能预算、已知问题
- 输出：性能前后指标、视觉/音频打磨变更、测试结果、发布就绪评估

## 约束
- 每阶段转换前用户批准
- 优化不得改变玩法行为
- 编排器不直接写文件
- 无参数时输出用法并退出

## 反例（不要这样）
- 优化改变玩法行为却未验证
- 只做性能不做视觉/音频/加固
- 低画质下特效不降级导致性能崩坏
- 跳过最低配置测试

## 反合理化表（借口 → 反驳）
| 借口（会怎么说） | 反驳（为什么不对） |
|---|---|
| 「优化顺手改了点玩法，感觉更好」 | 优化不得改变玩法行为，改变玩法会让加固与回归失效 |
| 「只做性能就够，视觉音频后面说」 | 只做性能不做视觉/音频/加固不达发布质量，签署会判 NEEDS MORE WORK |
| 「低画质不用管，高配用户多」 | 低画质下特效不降级会导致性能崩坏，最低配置用户无法运行 |

## Red Flags（违规信号）
- 优化后未做回归验证玩法不变
- 特效在低画质下不降级
- 跳过最低配置测试或浸泡/压力测试
- 签署只报性能指标、忽略视觉/音频/加固变更

## Verification（证据化验证门）
- [ ] 性能前后指标已对比预算（附指标数据）
- [ ] 优化后回归测试确认玩法未变（附回归结果）
- [ ] 最低配置测试与浸泡/压力测试已执行并记录结果
- [ ] 签署报告显式给出 READY FOR RELEASE / NEEDS MORE WORK 及遗留问题严重度
