# 资产审计

> **路径约定**：本技能中的 `src/`、`assets/`、`tests/`、`prototypes/` 等为项目级约定路径，落到 UE 项目时对应 `Source/<GameModule>/`、`Content/`、`Source/**/Tests/`、`Prototypes/`；完整映射见 `references/project-paths.md`。

## 何时使用
- 发布前做资产卫生检查
- 怀疑命名、尺寸、格式或管线不合规
- 需要清理孤立/缺失资产

## 流程
### 1. 读取规范
- 读取美术圣经/资产规范文档与 AGENTS.md 命名约定

### 2. 扫描资产目录
- 用 Glob 扫描 `assets/art|audio|vfx|shaders|data` 等目录

### 3. 执行合规检查
- 命名：匹配 `[category]_[name]_[variant]_[size].[ext]` 模式，全小写下划线
- 文件：纹理为 2 的幂次幂尺寸且格式正确（UI 用 PNG、3D 用压缩格式）、音频采样率/格式/时长达标、数据文件为合法 JSON/YAML 且符合 schema
- 孤立资产：在代码中搜索引用，无引用则标记
- 缺失资产：在代码中搜到的引用，验证文件是否存在

### 4. 输出审计报告
- 摘要（扫描总数、各类违规计数、整体健康 CLEAN/MINOR ISSUES/NEEDS ATTENTION）
- 分区：命名违规表、尺寸违规表、格式违规表、孤立资产表、缺失资产表、建议
- 给出 **Verdict：COMPLIANT / WARNINGS / NON-COMPLIANT**

## 输入/输出
- 输入：资产目录 + 规范文档
- 输出：资产审计报告 + verdict

## 约束
- 只读诊断，只产出报告不写文件
- 必须给出 verdict（COMPLIANT/WARNINGS/NON-COMPLIANT）
- 孤立资产只能建议删除，需人工复核

## 反例（不要这样）
- 擅自删除孤立资产（需人工复核后处理）
- 不读规范就按个人习惯判定命名合规
- 遗漏缺失引用检查，只查命名

## 反合理化表（借口 → 反驳）
| 借口（会怎么说） | 反驳（为什么不对） |
|---|---|
| 「孤立资产没人用了，直接删掉省空间」 | 孤立资产只能建议删除并需人工复核，擅自删会误伤仍在引用或待用的资源 |
| 「凭经验就知道这命名不规范，不用翻规范」 | 不读规范就按个人习惯判定命名合规，判定会失真且不可复现 |
| 「命名不合规就行，缺失引用不用查」 | 遗漏缺失引用会让运行时引用断裂漏网，审计必须命名/尺寸/格式/孤立/缺失全覆盖 |
| 「扫描完给个大概结论就行」 | 必须给出明确 verdict（COMPLIANT/WARNINGS/NON-COMPLIANT），否则用户无法决策 |

## Red Flags（违规信号）
- 报告缺少 verdict 关键词（COMPLIANT / WARNINGS / NON-COMPLIANT）
- 未读取规范文档就凭个人习惯判定命名合规
- 擅自删除孤立资产或写文件（本技能只读诊断）
- 只查命名/尺寸，遗漏缺失引用检查或孤立资产检查

## Verification（证据化验证门）
- [ ] 报告含 verdict，且与各违规表计数一致（附摘要证据）
- [ ] 命名判定依据明确引用了规范文档/AGENTS.md 约定，而非个人习惯
- [ ] 孤立资产均注明「建议删除 + 需人工复核」，缺失资产均有对应引用来源
- [ ] 全程只读，未删除或修改任何资产文件
