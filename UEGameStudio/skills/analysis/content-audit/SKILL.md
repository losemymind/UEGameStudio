# 内容审计

## 何时使用
- 盘点某个系统或全项目的内容完成度
- 量化"计划 vs 已实现"的缺口
- 里程碑评审前确认内容进度

## 流程
### 1. 上下文收集
- 读取 `design/gdd/systems-index.md` 获取系统清单、分类与 MVP 优先级
- L0 预扫描：Grep 含内容计数关键词的 GDD，全量只读匹配到的 GDD；纯机制类 GDD 标记"无可审计计数"
- 提取显式内容计数/列表（敌人、关卡、物品、技能、对话、任务等），构建内容清单表

### 2. 实现扫描
- 按内容类型 Glob 对应目录统计已实现数量（场景/角色数据/物品/技能/对话/任务）
- 在报告中说明：计数是近似值，无法区分发布内容与编辑器/测试资产

### 3. 缺口报告
- 生成缺口表：`系统 | 内容类型 | 规划 | 已实现 | 缺口 | 状态`
- 状态分类：COMPLETE（≥100%）、IN PROGRESS（50–99%）、EARLY（1–49%）、NOT STARTED（0）
- 若 NOT STARTED/EARLY 且属 MVP/Vertical Slice 或阻塞下游 → 标 HIGH PRIORITY
- 汇总：总规划、总已实现、总缺口百分比

### 4. 输出
- 全量/单系统模式：呈现缺口表，询问是否写完整报告到 `docs/content-audit-[日期].md`
- `--summary` 模式：只打印表格不写文件

## 输入/输出
- 输入：GDD（systems-index + 各系统 GDD）+ 实现目录
- 输出：缺口表 + 摘要 + 可选完整报告文件

## 约束
- 报告为主，写文件前必须征得同意
- 计数需声明近似性，不得把场景/UI/测试资产误判为内容
- 给出明确 verdict（COMPLETE）
- 未给计数的 GDD 要标注"未指定"作为设计缺口

## 反例（不要这样）
- 把编辑器/测试资产计入已实现内容
- 不读 systems-index 就判断优先级
- 未经同意直接写报告文件
- 对"未指定计数"的 GDD 不做任何标记

## 反合理化表（借口 → 反驳）
| 借口（会怎么说） | 反驳（为什么不对） |
|---|---|
| 「场景和测试资产也算内容，凑个数」 | 编辑器/测试资产不是发布内容，计入会虚报完成度，计数必须声明近似性并排除它们 |
| 「优先级我大概有数，不用读 systems-index」 | 不读 systems-index 就无法正确判定 MVP/Vertical Slice 与 HIGH PRIORITY，优先级会失真 |
| 「直接写好报告文件，省得再问」 | 写文件前必须征得同意，擅自写会污染仓库并越过用户决策 |
| 「这个 GDD 没写数量，跳过不管」 | 未给计数的 GDD 必须标注\"未指定\"作为设计缺口，否则缺口被掩盖 |

## Red Flags（违规信号）
- 未读取 systems-index 就判定系统优先级或 HIGH PRIORITY
- 把场景/UI/编辑器/测试资产计入「已实现」内容
- 未经同意直接写报告文件（非 --summary 模式）
- 未对「未指定计数」的 GDD 做任何标记
- 缺口表缺少状态分类（COMPLETE / IN PROGRESS / EARLY / NOT STARTED）

## Verification（证据化验证门）
- [ ] 缺口表含 系统|内容类型|规划|已实现|缺口|状态 六列，状态分类完整（附表格证据）
- [ ] 计数声明了近似性，且未包含场景/UI/编辑器/测试资产
- [ ] 未指定计数的 GDD 被标注「未指定」，纯机制类 GDD 被标注「无可审计计数」
- [ ] 写报告文件（--summary 除外）前已征得用户同意，非 summary 报告路径含日期后缀
