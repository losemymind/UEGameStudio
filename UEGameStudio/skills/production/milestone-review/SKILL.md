# 里程碑评审

## 何时使用
- 里程碑检查点
- 评估里程碑截止的完备度与 Go/No-Go
- 试玩测试结束后，需要产出结构化的试玩测试报告

## 流程
### 阶段 0：解析参数
- 提取里程碑名（current 或指定名）与评审模式

### 阶段 1：加载里程碑数据
- 读 `production/milestones/` 定义（current 取最近修改），读该里程碑内全部 sprint 报告
- 如有试玩测试数据，加载 `production/playtests/` 下的试玩记录

### 阶段 2：扫描代码健康
- 扫描 TODO/FIXME/HACK 标记，查风险登记册

### 阶段 3：生成里程碑评审
- 输出：概览、功能完整性（完全/部分/未开始）、质量指标（S1/S2/S3 bug、覆盖率、性能）、代码健康、风险评估、速率分析、范围建议（Protect/At Risk/Cut）、Go/No-Go、行动项
- 如有试玩测试数据，合并试玩测试报告（见下方试玩测试报告章节）

### 阶段 3b：Producer 风险评估
- 按评审模式委派 game-producer（PR-MILESTONE 门），其裁定（ON TRACK/AT RISK/OFF TRACK）指导 Go/No-Go
- OFF TRACK 默认 NO-GO，除非用户显式覆盖；AT RISK 用决策点定 CONDITIONAL GO/NO-GO/GO

### 阶段 4：保存评审
- 请求写 `production/milestones/[name]-review.md`

### 阶段 5：下一步
- gate-check（若跨阶段边界）、sprint-plan 调整下一 sprint

## 试玩测试报告（合并自 playtest-report）

试玩测试是里程碑评审中的重要数据来源，提供来自真实玩家的定性反馈和定量指标。里程碑评审中如有试玩数据，必须整合为结构化报告。

### 试玩测试报告结构
1. **测试概览**：
   - 测试日期、时长、参与人数（玩家数 + 观察员数）
   - 测试目标（本次试玩想验证什么——核心玩法乐趣/难度曲线/新手引导/特定系统）
   - 测试环境（远程/线下、设备/平台、构建版本）
2. **观察员笔记**：
   - 按时间线或玩家分组整理观察员记录
   - 标注关键事件：玩家在哪卡住、何时表现出困惑/沮丧/兴奋
   - 引用玩家原话（加引号），标注情绪（正面/负面/中性）
   - 每个观察点标注对应的游戏系统或功能
3. **玩家反馈汇总**：
   - 按主题聚类：战斗/移动/UI/难度/叙事/新手引导/技术问题
   - 每个主题下列出：正面反馈（数量）、负面反馈（数量）、具体建议（数量）
   - 高频反馈（≥30% 玩家提及）标注 `[HIGH FREQUENCY]`
   - 引用代表性玩家原话，保留原始措辞
4. **定量指标**：
   - 平均游戏时长、完成率（完成试玩目标的玩家比例）
   - 各关卡/挑战的通过率、平均耗时、重试次数
   - 关键交互的使用率（如"多少玩家使用了闪避键"）
   - 崩溃/卡死次数、性能问题报告数
5. **关键发现**：
   - 按严重程度（Critical/Major/Minor）列出发现的问题
   - 每个发现含：现象描述、影响范围、观察依据（引用观察员笔记或玩家反馈）、建议优先级
6. **行动项**：
   - 按优先级排序的行动项列表
   - 每个行动项含：要做什么、关联的发现、负责角色、目标冲刺
   - 区分"必须修复"、"建议改进"、"考虑加入"

### 试玩测试报告示例格式
```
## 试玩测试报告：Alpha 试玩 #2
**日期**：2024-03-15 | **时长**：3 小时 | **参与**：12 名玩家 + 3 名观察员
**目标**：验证战斗手感、难度曲线、新手引导

### 观察员笔记（精华）
- 6/12 名玩家在教程关卡的第 3 个房间卡住超过 2 分钟，反复尝试跳跃平台
  - 玩家 A："这平台怎么跳不过去？"（困惑）
  - 观察：平台间距刚好超出基础跳跃距离，玩家未发现需要冲刺跳跃
- 10/12 名玩家在首次战斗胜利后表现出兴奋反应
  - 玩家 F："手感真不错！"（正面）
  - 观察：打击感反馈（屏幕震动+音效+粒子）获得了最多的自发好评

### 玩家反馈汇总
| 主题 | 正面 | 负面 | 建议 |
|---|---|---|---|
| 战斗 | 10 | 2 | 3 |
| 移动 | 5 | 8 | 4 |
| UI | 3 | 7 | 5 |

[HIGH FREQUENCY] 移动跳跃手感偏滑（8/12 负面，建议增加空中摩擦）

### 关键发现
- [Critical] 教程关卡第 3 房间平台间距超出基础跳跃距离，6/12 玩家卡住（观察依据：观察员笔记）
- [Major] 跳跃手感偏滑，8/12 玩家反馈（建议增加空中摩擦参数）
- [Minor] 生命值 UI 在战斗中太小，3/12 玩家未注意到自己被击中

### 行动项
1. [P0] 调整教程关卡平台间距或增加冲刺提示 → 关联发现 1 → 关卡设计师 → Sprint 5
2. [P1] 增加空中摩擦参数 → 关联发现 2 → 玩法程序员 → Sprint 5
3. [P2] 战斗中放大生命值 UI → 关联发现 3 → UI 设计师 → Sprint 6
```

### 试玩测试报告约束
- 观察员笔记必须区分"观察到的行为"与"观察员的推测"，推测需标注 `[推测]`
- 玩家反馈必须标注频率（如"8/12 玩家"），避免"很多玩家觉得..."类模糊表述
- 定量指标必须给出具体数字，不用"大多数"、"少数"等模糊词
- 行动项必须关联到具体发现，不凭空创建行动项
- 玩家原话保留原始措辞，不修改语法或措辞（即使有语法错误）
- 试玩测试报告中的发现必须在里程碑评审的风险评估中引用

## 输入/输出
- 输入：里程碑名、里程碑定义、sprint 报告、风险登记、试玩测试数据（如有）
- 输出：里程碑评审文档（含 Go/No-Go 建议与行动项）+ 试玩测试报告（如有）

## 约束
- OFF TRACK 不得擅自判 GO
- 写文件前须用户批准
- Go/No-Go 须附理由
- 试玩测试报告必须在里程碑评审中引用，不能独立存在而不影响评审结论
- 观察员笔记必须区分观察与推测，推测标注 `[推测]`
- 玩家反馈必须标注频率，定量指标必须给出具体数字

## 反例（不要这样）
- 对 OFF TRACK 里程碑直接给 GO
- 只列功能完成度，缺质量指标/风险/速率
- 未附理由的 Go/No-Go
- 写文件前未请求批准
- 试玩测试报告中有数据但不引用到里程碑评审的风险评估中
- 观察员笔记混淆观察与推测（如"玩家觉得不好玩"——这是推测，应写"3 名玩家在 5 分钟后退出游戏"）
- 玩家反馈用"很多玩家"代替具体数字
- 行动项凭空创建，不关联到具体发现

## 反合理化表（借口 → 反驳）
| 借口（会怎么说） | 反驳（为什么不对） |
|---|---|
| 「OFF TRACK 但大部分功能做完，给 GO 也合理」 | OFF TRACK 默认 NO-GO 是硬约束，只有用户显式覆盖才能改，擅自判 GO 会误导发布决策。 |
| 「质量指标不重要，功能齐全就行」 | 约束要求输出 S1/S2/S3 bug、覆盖率、性能，只列功能完成度会遗漏发布风险。 |
| 「Go/No-Go 结论清楚，理由就不写了」 | Go/No-Go 必须附理由，无理由的建议无法被复核，等于没有评估。 |
| 「评审文档先写了再说，批准流程走个形式」 | 写文件前须用户批准是硬约束，未经批准写盘会污染里程碑记录。 |
| 「试玩数据看一遍就行，正式报告里提两句够了」 | 试玩测试报告必须结构化（观察员笔记/玩家反馈/定量指标/关键发现/行动项），不能只提两句。 |
| 「玩家反馈写『很多玩家觉得』就行，不用数」 | 反馈必须标注具体频率（如 8/12），模糊表述无法判断严重程度。 |
| 「观察员觉得玩家无聊，直接写『玩家感到无聊』」 | 观察员笔记必须区分观察与推测，推测必须标注 `[推测]`，不能把推测当事实。 |

## Red Flags（违规信号）
- OFF TRACK 里程碑被直接判为 GO（无用户显式覆盖）
- 评审中缺失质量指标（S1/S2/S3 bug、覆盖率、性能）或风险/速率分析
- Go/No-Go 结论未附任何理由
- 未请求批准就写入 `production/milestones/[name]-review.md`
- AT RISK 场景未走 CONDITIONAL GO / NO-GO / GO 决策点
- 试玩测试数据存在但里程碑评审中未引用
- 观察员笔记混淆观察与推测（推测未标注 `[推测]`）
- 玩家反馈用模糊表述（"很多"、"大多数"）代替具体数字
- 行动项凭空创建，未关联到具体发现

## Verification（证据化验证门）
- [ ] 评审文档含功能完整性、质量指标、代码健康、风险评估、速率分析、范围建议、Go/No-Go、行动项（逐项核对）
- [ ] Producer 裁定有记录，且 OFF TRACK 场景有 NO-GO 或用户显式覆盖证据
- [ ] Go/No-Go 结论附有可复述的理由
- [ ] 写文件前有用户批准记录（未擅自写盘）
- [ ] 试玩测试报告（如有）含测试概览/观察员笔记/玩家反馈汇总/定量指标/关键发现/行动项，反馈含具体频率数字
- [ ] 试玩测试中的关键发现已在里程碑评审的风险评估中引用
- [ ] 观察员笔记中推测已标注 `[推测]`，玩家原话保留原始措辞
